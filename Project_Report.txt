                                PROJECT REPORT
                             WEATHER APPLICATION
================================================================================

1. INTRODUCTION
---------------
This Weather Application is a modern, responsive web application built with
React.js. It provides real-time weather information based on the user's
current location or any searched city worldwide. The application features a 
clean UI with animated weather icons, a live clock, and detailed weather 
metrics.

2. TECHNOLOGIES & TOPICS USED
-----------------------------

A. React.js
-----------
*   Why Used: Chosen as the primary frontend library for its component-based 
    architecture, which allows for building a modular and maintainable UI. It 
    efficiently handles state changes and re-renders only necessary components.
*   Where Used: Used for the entire application structure.
    - src/App.js: Main entry point.
    - src/currentLocation.js: Manages local weather display.
    - src/forcast.js: Manages city search and forecast display.

B. HTML5 & CSS3
---------------
*   Why Used: Standard for web structure (HTML) and visual styling (CSS). Used 
    to create a responsive layout that works across desktop and mobile devices.
*   Where Used: 
    - src/App.css: Contains the main UI styles, gradients, and layouts.
    - src/index.css: Baseline styles and font imports.

C. JavaScript (ES6+)
--------------------
*   Why Used: Provides the logic layer of the application, including handling 
    APIs, asynchronous operations, and data processing.
*   Where Used: In all .js files for logic and state management.

D. Axios (Library)
------------------
*   Why Used: A popular promise-based HTTP client for the browser. It was 
    chosen for searching cities because it handles JSON parsing automatically 
    and simplifies asynchronous code.
*   Where Used: 
    - src/forcast.js: Used to fetch weather data when a user searches for a specific city.

E. Fetch API (Native)
---------------------
*   Why Used: A native browser API used for network requests. It was used in 
    the location detection component for direct API calls.
*   Where Used: 
    - src/currentLocation.js: Used to fetch initial weather data based on detected coordinates.

F. Geolocation API (Native)
---------------------------
*   Why Used: To automatically detect the user's current position (latitude and 
    longitude) without requiring manual input, providing an "instant" local 
    weather experience.
*   Where Used: 
    - src/currentLocation.js: Uses navigator.geolocation to request user permissions and get position.

G. OpenWeatherMap API
---------------------
*   Why Used: A reliable external data source for real-time weather information. 
    It provides comprehensive data including temperature, humidity, visibility, 
    and wind speed.
*   Where Used: 
    - Interfaced in src/apiKeys.js and called in src/currentLocation.js and src/forcast.js.

H. React Hooks (useState & useEffect)
--------------------------------------
*   Why Used: To manage state and lifecycle in functional components without 
    needing classes. It makes the code cleaner and easier to reason about.
*   Where Used: 
    - src/forcast.js: Uses useState for city queries and weather data, and useEffect for initial data loading.

I. react-live-clock (Library)
-----------------------------
*   Why Used: To provide a real-time, ticking clock on the dashboard, enhancing 
    the utility of the application beyond just weather.
*   Where Used: 
    - src/currentLocation.js: Displays the HH:mm:ss clock.

J. react-animated-weather (Library)
------------------------------------
*   Why Used: To provide visually appealing, dynamic SKYCONS (animated icons) 
    that match the current weather conditions (e.g., Rain, Clouds, Clear Day).
*   Where Used: 
    - src/currentLocation.js & src/forcast.js: Icons change dynamically based on API responses.

3. LOGIC & WORKFLOW
-------------------
1. Initial Load: The app requests geolocation access. If granted, it fetches 
   weather for the user's coordinates. If denied, it defaults to a standard 
   location (example: Delhi).
2. UI Updates: React updates the state with temperature, city name, humidity, 
   and weather status.
3. City Search: In the forecast section, users can type a city name. Axios 
   sends a request to the OpenWeatherMap API, and the UI updates to show that 
   city's data.
4. Visual Sync: Both components use a common mapping (switch-case) to sync the 
   weather description (e.g., "Haze") with the correct animated icon.
