================================================================================
                                PROJECT REPORT
                             WEATHER APPLICATION
================================================================================

1. INTRODUCTION
---------------
This Weather Application is a modern, responsive web application built with
React.js and bundled with Vite. It provides real-time weather information based 
on the user's current location or any searched city worldwide. The application 
features a clean UI with animated weather icons, a live clock, and detailed 
weather metrics.

2. TECHNOLOGIES & TOPICS USED
-----------------------------

A. React.js
-----------
*   Why Used: Chosen as the primary frontend library for its component-based 
    architecture, which allows for building a modular and maintainable UI. It 
    efficiently handles state changes and re-renders only necessary components.
*   Where Used: Used for the entire application structure.
    - src/App.jsx: Main layout component.
    - src/currentLocation.jsx: Manages local weather display & geolocation.
    - src/forcast.jsx: Manages city search and forecast display.
    - src/Clock.jsx: Modular real-time ticking digital clock component.
    - src/WeatherIcon.jsx: Weather icon wrapper component.

B. Vite (Build Tool & Development Server)
-----------------------------------------
*   Why Used: Modern frontend tooling that replaces legacy Create React App 
    (CRA). Vite uses native ES modules in the browser for instantaneous Hot 
    Module Replacement (HMR), resolves build-tool package bloat (dropping 
    over 1,500 obsolete packages), achieves 0 dependency vulnerabilities, and 
    builds the production bundle in ~300ms.
*   Where Used: 
    - vite.config.js: Configuration for React plugin and environment variables.
    - index.html: Application root entry point.

C. HTML5 & CSS3
---------------
*   Why Used: Standard for web structure (HTML) and visual styling (CSS). Used 
    to create a responsive layout that works across desktop and mobile devices.
*   Where Used: 
    - index.html: Application root template.
    - src/App.css: Contains the main UI styles, gradients, and layouts.
    - src/index.css: Baseline styles and font imports.

D. JavaScript (ES6+)
--------------------
*   Why Used: Provides the logic layer of the application, including handling 
    APIs, asynchronous operations, and data processing.
*   Where Used: In all .jsx and .js files for logic and state management.

E. Axios (Library)
------------------
*   Why Used: A popular promise-based HTTP client for the browser. It was 
    chosen for searching cities because it handles JSON parsing automatically 
    and simplifies asynchronous code.
*   Where Used: 
    - src/forcast.jsx: Used to fetch weather data when a user searches for a specific city.

F. Fetch API (Native)
---------------------
*   Why Used: A native browser API used for network requests. It was used in 
    the location detection component for direct API calls.
*   Where Used: 
    - src/currentLocation.jsx: Used to fetch initial weather data based on detected coordinates.

G. Geolocation API (Native)
---------------------------
*   Why Used: To automatically detect the user's current position (latitude and 
    longitude) without requiring manual input or third-party wrappers, providing 
    an "instant" local weather experience.
*   Where Used: 
    - src/currentLocation.jsx: Uses navigator.geolocation to request user permissions and get position.

H. OpenWeatherMap API
---------------------
*   Why Used: A reliable external data source for real-time weather information. 
    It provides comprehensive data including temperature, humidity, visibility, 
    and wind speed.
*   Where Used: 
    - Interfaced in src/apiKeys.js and called in src/currentLocation.jsx and src/forcast.jsx.

I. React Hooks (useState & useEffect)
--------------------------------------
*   Why Used: To manage state and lifecycle in functional components without 
    needing classes. It makes the code cleaner, lightweight, and easier to reason about.
*   Where Used: 
    - src/forcast.jsx: Uses useState for city queries and weather data, and useEffect for initial data loading.
    - src/Clock.jsx: Uses useState and useEffect for a ticking timer.

J. Custom Clock Component (src/Clock.jsx)
-----------------------------------------
*   Why Used: Replaces heavy legacy dependencies (react-live-clock and moment.js) 
    with a lightweight, zero-dependency native component. It saves over 800 KB of 
    bundle size and eliminates common UMD module compatibility issues.
*   Where Used: 
    - src/currentLocation.jsx: Displays the live HH:mm:ss clock on the dashboard.

K. react-animated-weather & WeatherIcon Wrapper
-----------------------------------------------
*   Why Used: To provide visually appealing, dynamic SKYCONS (animated icons) 
    that match the current weather conditions (e.g., Rain, Clouds, Clear Day). 
    An ESM adapter (src/WeatherIcon.jsx) ensures seamless CJS/ESM interop in modern bundlers.
*   Where Used: 
    - src/currentLocation.jsx & src/forcast.jsx: Icons change dynamically based on API responses.

3. LOGIC & WORKFLOW
-------------------
1. Initial Load: The app requests geolocation access. If granted, it fetches 
   weather for the user's coordinates. If denied, it defaults to a standard 
   location (Delhi).
2. UI Updates: React updates the state with temperature, city name, humidity, 
   and weather status.
3. City Search: In the forecast section, users can type a city name. Axios 
   sends a request to the OpenWeatherMap API, and the UI updates to show that 
   city's data.
4. Visual Sync: Both components use a common mapping (switch-case) to sync the 
   weather description (e.g., "Haze") with the correct animated icon.
